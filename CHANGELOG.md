- **`kaomoji-strip.js`** (`assets/js/dev-projects/kaomoji-strip.js`): New ES6 module, `initKaomojiStrip(mountSelector)`, that owns the kaomoji.click strip's markup *and* its behaviour in one place, so `index.html` and `personal.html` share a single copy instead of two. Consolidates what used to be inline in `index.html`: the strip's HTML (`stripMarkup()`), the `kaomoji-copy` `postMessage` listener with `event.origin` validation, and the iframe `mouseenter`/`mouseleave` bridge that fakes section-level `mouseleave`/`mouseenter` so the cursor-chat bubble doesn't hang at the iframe boundary (pointer events inside the iframe never reach the parent document). Replaces its mount placeholder with the rendered `<section>` rather than filling it, so no wrapper `<div>` enters the layout. Returns `{ section, cursorTrigger }`, or `null` if the mount selector isn't found (so a page can drop the strip by deleting its placeholder alone). Deliberately does **not** call `initCursorChat` itself — `index.html` registers ten hover triggers in one call and `cursor-chat.js` builds one bubble per call, so the page has to own that call and compose the returned `cursorTrigger` in. Ordering matters: the strip must be mounted before the page's `initCursorChat()` call, because `cursor-chat.js` resolves each trigger's selector once at init and silently skips selectors matching nothing.

- **Planner: drag-and-drop was broken (unstyled, non-fixed floating clone; no cursor/selection guard) in the homepage's compact embed** (`assets/js/dev-projects/planner/drag.js`): `beginDrag()` appends the floating drag clone to `document.body` and adds a `pl-board-dragging` class to `<body>` itself (for a whole-page `cursor: grabbing` / `user-select: none` guard) — both styled by `project-planner.css` rules scoped `[data-project="planner"] .pl-card-clone` / `[data-project="planner"] body.pl-board-dragging`. Fix: `beginDrag()` now temporarily sets `data-project="planner"` on `<html>` for the gesture's duration (restored — not just removed — in `cleanupPointerDrag()`, and only if this gesture is the one that added it, so a page where it's already permanently present, like `projects/planner.html`, is never left without it afterward).

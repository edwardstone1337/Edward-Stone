- **Cursor chat on the Kaomoji strip, reacting to a copy** (`index.html`, `assets/previews/kaomoji/index.html`): the existing `initCursorChat` feature (`assets/js/dev-projects/cursor-chat.js`, already live on the homepage and resume) gains a trigger reading "Try clicking one", which becomes "Great choice" once the visitor actually copies a kaomoji. The preview iframe signals the copy with `postMessage({ type: 'kaomoji-copy' })` — **this is the first postMessage receiver in the codebase**; `theme-toggle.js` has always broadcast `theme-change` but nothing ever listened. The message carries no text: it reports only *that* a copy happened, and the parent owns the wording, so nothing crossing the iframe boundary is ever rendered and no sanitisation is required. The receiver validates `event.origin` against `window.location.origin` (the embed is same-origin by construction — relative `src` plus `allow-same-origin`) and filters on message type. Only a *successful* copy notifies; a failed clipboard write leaves the message alone rather than wrongly congratulating. `cursor-chat.js` itself is untouched: its hover handler reads `trigger.message` when the event fires rather than at init, so holding the trigger object by reference and mutating it is enough. The message resets to "Try clicking one" when the pointer leaves the strip, so the acknowledgement belongs to the visit rather than sticking for the rest of the session.
- **Kaomoji cursor chat covers the whole section, including its padding** (`index.html`): the trigger is `#strip-kaomoji`, so the bubble appears the moment the pointer enters the section rather than only over the bear, heading or button. That was not possible while the preview was in play, because pointer events inside an iframe never reach the parent document and the bubble hung at the boundary as the cursor moved on. `mouseenter`/`mouseleave` on the iframe *element* do fire in the parent, so they bridge it: entering the preview dispatches a synthetic `mouseleave` on the section and exiting dispatches a synthetic `mouseenter`. A flag marks those synthetic events so the message reset ignores them and only fires on a real exit.

### Fixed
- **The Flip 7 preview never rendered** (`index.html`): the strip's `<iframe>` carried `visibility: hidden` in its inline `style`, and nothing in `assets/js/` ever set it back — no `onload`, no `postMessage` handshake, no reveal script. The playable mini-game had been shipping as an empty frame. Removed; the preview now renders. The neighbouring Kaomoji iframe never had the property, so this was specific to Flip 7.
- **Strip modifiers setting only `--dp-strip-title-color` were silently ignored** (`dev-styles.css`, `docs/strip-branding-spec.md`): `.dp-strip-title` paints a gradient from `--dp-strip-title-from`/`-to` and clips it to the text; both defaulted to `var(--dp-strip-title-color)` **in `:root`**. Custom properties are substituted where they are declared, not where they are used, so that default resolved against the *default* title colour and froze there — SCP Reader declared `#ffffff` and Kaomoji `#F2F0EE`, and both rendered Fair Share's mint `#eafcf8`. Only Flip 7 escaped, by setting the gradient pair explicitly. The fallback pair is now declared on `.dp-strip`, the element the modifiers land on, so a strip that sets just `title-color` gets it; explicit `title-from`/`-to` still win on source order. Visible effect: the SCP Reader title is now white as declared, and Kaomoji off-white. Documented as a gotcha in the strip spec.
- **Raw hex in `dev-styles.css`** (`dev-styles.css`): `.dp-strip--kaomoji .dp-strip-media` hardcoded `background: #141414` and `border: 1px solid #5a5a5a`, against the project rule that the shared component layer never carries a colour value. Both were redundant — base `.dp-strip-media` already reads all three from tokens — so the declarations are deleted rather than re-tokenised. `check-token-hygiene.sh` never caught this: it audits `--dp-*` declarations, not property values.
- **Kaomoji preview tooltip cropped by the iframe** (`assets/previews/kaomoji/index.html`): the tooltip is `position: fixed` inside the embed, and an iframe cannot paint outside its own box, so on the top row it was clipped by the frame edge. It now flips below the card when there is no room above and clamps on both axes, verified fully inside the frame at 240px through 525px.
- **Preview marquee stayed frozen after a copy** (`assets/previews/kaomoji/index.html`): clicking a kaomoji focuses it, and the `.km-row:focus-within` pause rule then held that row still after the pointer had left. Hover and keyboard focus now hold the pause independently, and only a keyboard focus holds it — input modality is tracked explicitly via `pointerdown`/`keydown` rather than read off `:focus-visible`, which can still report true for a pointer focus after any earlier key press.
